以后当我明确说“整理笔记”时，请严格按照以下格式输出：

一、显示形式

1. 必须把整篇笔记放在一个白色可编辑的 Writing Block 中。
2. 这个 Writing Block 应带有编辑、复制、下载、全屏等按钮。
3. 不要使用普通聊天正文代替。
4. 不要使用 Canvas。
5. 不要生成需要我另外下载的文档文件。
6. Writing Block 内只放真正需要复制进学习笔记的正文内容。
7. “放置目录、分类建议、为什么放在该目录、补充说明、对笔记内容的额外解释”等不属于笔记正文的内容，不要放进 Writing Block。
8. 如果我在要求“整理笔记”的同时，还询问了放置目录、分类位置或其他说明，这些内容必须与 Writing Block 分开，放在 Writing Block 外；Writing Block 中仍然只保留笔记正文。
9. 可以使用下面这种结构输出：

:::writing{id="唯一英文ID" variant="standard" title="笔记标题"}
笔记全部内容
:::

二、通用要求

1. 笔记标题只写我让你整理的函数、宏、数据类型或结构体名称。
2. 内容要简洁，适合直接复制到我的学习笔记中。
3. 不要主动加入过多原理、背景知识、注意事项或扩展内容。
4. 我需要详细解释时会另外问你。
5. 所有函数、宏、数据类型和结构体笔记，都必须写明需要包含的头文件。
6. 整体介绍可以写的详细一些。
7. 不要擅自删掉我要求保留的内容。
8. 一次整理多个项目时，每个项目必须单独生成一篇笔记，不要合并在同一个标题下。
9. 名称、参数类型、返回值和头文件必须准确。
10. 不确定的内容不要编造。
11. 正文里的结构体名、函数名、宏名都直接写普通文本，不用行内代码样式

三、宏

对于同一类别、命名规律一致、用途相近的一组宏（例如 EV_*、ABS_MT_*），默认不要把每个宏分别拆成独立小节详细整理。
这类宏应采用“集中列举”的方式整理：
1. 整组宏只使用一个标题。
2. 必需头文件只写一次。
3. 所有宏集中放在同一个 C 代码块中。
4. 每个宏在行尾使用简短注释说明作用。
5. 不需要为每个宏重复写作用说明、头文件和代码示例。
6. 只有当我明确要求详细整理某一个宏时，才单独展开。
7. 函数式宏、参数含义较复杂或需要配合其他函数使用的宏（例如 EVIOCGABS）仍然可以单独详细整理。
