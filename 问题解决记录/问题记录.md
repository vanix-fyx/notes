### VS Code 解析 Linux 内核头文件失败，需要正确加载内核配置宏

**问题现象：** 使用 VS Code Remote SSH 开发 Linux ARM 驱动时，包含 linux/of_irq.h 出现红线，提示找不到 mach/irqs.h，并导致 IntelliSense 无法正常检查源文件的语法错误。

**原因分析：** 内核头文件会根据 CONFIG_SPARSE_IRQ 等配置宏选择不同的代码分支。由于 IntelliSense 没有正确加载内核配置宏，错误地进入了包含 mach/irqs.h 的分支。

仅配置 includePath 无法解决此问题，因为 includePath 只指定头文件搜索路径，不会自动加载内核配置宏。

**解决方法：**

1. 确认修改的是当前 Remote SSH 项目实际使用的 .vscode/c_cpp_properties.json，而不是本地 Windows 上的配置文件。
    
2. 在原有配置中增加 forcedInclude，指定当前内核源码树中的 include/linux/kconfig.h。
    
3. 该头文件会进一步包含 generated/autoconf.h，为 IntelliSense 提供内核配置宏。
    
4. 执行 C/C++: Reset IntelliSense Database，重置解析数据库。
    

本次使用的配置路径：

```
/home/book/100ask_imx6ull-sdk/Buildroot_2020.02.x/output/build/linux-origin_master/include/linux/kconfig.h
```

**验证结果：** 修改后头文件报错红线消失，IntelliSense 恢复正常。

**注意：**

- forcedInclude 的路径必须与当前项目实际使用的内核源码树一致。
    
- 可以通过 C/C++: Log Diagnostics 查看实际生效的头文件路径、宏定义和编译器配置。
    
- 此问题属于编辑器 IntelliSense 解析配置问题，不代表驱动实际编译失败。
    
- 修改 forcedInclude 只影响编辑器代码解析，不会修改驱动源码或实际编译配置。

### GPIO 下降沿中断在按键松开时误触发，可通过输入迟滞改善

**问题现象：** 两个按键均配置为下降沿中断，KEY1 正常，但 KEY2 每次按下和松开都会触发一次中断。通过 `/proc/interrupts` 确认，每次按下和松开时中断计数均增加 1。

**原因分析：** KEY2 外部具有 10kΩ 上拉电阻和 100nF 滤波电容。松开按键时，电容通过上拉电阻充电，GPIO 输入电压逐渐上升。如果电压在输入判断阈值附近受到噪声或触点抖动影响，可能产生额外的高低电平切换，从而触发下降沿中断。

**解决方法：** 将 KEY2 的 PAD 配置由 0x000010B0 修改为 0x000110B0，开启 HYS（施密特触发输入迟滞），问题得到解决。

开启 HYS 后，GPIO 使用不同的高、低电平切换阈值，可以避免输入电压在阈值附近小幅波动时反复改变逻辑状态。

**注意：**

- 本次现象与输入阈值附近的电平波动相符，但没有示波器波形，无法完全确定干扰来源。
    
- RC 滤波可以抑制部分按键抖动，因此机械触点多次抖动不一定产生多次中断。
    
- HYS 可以提高输入抗干扰能力，但不能完全替代按键消抖。
